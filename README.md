# Artemis-Financial
Final Project for CS-350

Briefly summarize your client, Artemis Financial, and its software requirements. Who was the client? What issue did the company want you to address?
Artemis Financial is a consulting firm that has asked to increase the security of their RESTful application. The company itself handles individualized financial plans for its customers and helps them save money to accomplish their goals. I was asked to address security issues that existed within the software by defining an algorithm cipher that would be of best fit for the program, then generating a self-signed certificate, and configuring the application to enable TLS and HTTPS. After all was said and done, we had an application that could be run through a dependency check for final verification. After ensuring that no vulnerabilities were added to the application we were able to wrap everything up and return it to the customer. 

What did you do well when you found your client’s software security vulnerabilities? Why is it important to code securely? What value does software security add to a company’s overall well-being?
When checking for software security vulnerabilities I started by running a simple dependency check to get an idea of what might be wrong with the program. From there I scanned through the dependency check to see which of the items held within were actual security vulnerabilities and which were just issues with the scanning tool. I think the aspect that I did best on was my code quality, by looking through various examples and studying how individuals programmed similar issues like this I was able to ensure the highest code quality with the lowest amount of additional vulnerabilities. It's important to code securely because without a high level of code security you can end up in a situation where you just keep adding more and more issues to the program, opening up a client to a whole host of unconventional attacks that they might not be prepared for. The value of software security comes in the form of time and money saved, by avoiding software security issues to begin with you're able to dedicate that time and resources to things that actually impact the company as opposed to patching holes in a sinking boat. 

Which part of the vulnerability assessment was challenging or helpful to you?
For me, the biggest challenge in the vulnerability assessment was picking through the various vulnerabilities and determining which of them were actually something to be concerned about and which were just false flags. Picking through version numbers and checking transitional dependencies was a challenge. Sometimes the integration of a singular dependencies introduced a whole host of transitional dependencies that needed to be checked with the same level of granularity as the normal ones. It was interesting though, through learning about weaknesses in transitional dependencies I was able to see how including things that you didn't write could lead to a whole host of issues and how so many CVE's come into existence. It often isn't the original dependency that's the issue, it's the open source software that it's built on. Whether that weakness be a simple memory address not being freed or some other simple issue, it all ties back to code quality and code security. A single dent in the armor is all it takes. 

How did you increase layers of security? In the future, what would you use to assess vulnerabilities and decide which mitigation techniques to use?
I increased the layers of security by using a multilayered approach to security as opposed to using just one. I ensured that any information in transit would be protected by configuring TLS and enabling HTTPS and by implementing a certificate that could be used to verify the identity of the site itself. From there I added a SHA-256 hashing algorithm that could be used to support a checksum verification which improved confidence about data integrity. After that the usage of Maven's dependency check tool allowed me to see which of the programs dependencies were most likely to result in some kind of vulnerability. In the future I'd like to integrate more tools like this, maybe something a bit more proactive than a standard static testing tool. Due to the nature of how vulnerabilities are found, and what it takes for them to be integrated into the dependency check we can only be sure about active vulnerabilities. Something that looks at how memory is handled, or runtime efficiency might be useful in more memory intensive languages like C, or C++, to ensure that memory leaks or open addresses aren't something that could be abused. 

How did you make certain the code and software application were functional and secure? After refactoring the code, how did you check to see whether you introduced new vulnerabilities and you use that might be helpful in future assignments or tasks?
I made sure that the code and software application were functional and secure by using the tools provided and secure coding practices. After refactoring the code, and ensured that it compiled and ran correctly, I was able to run a dependency check to ensure that I hadn't introduced new issues. Comparing that first dependency check with the final I was able to move forward with a degree of certainty about what I had completed.
